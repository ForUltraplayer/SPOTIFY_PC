# 기능 검증 기록

2026년 10월 26일에 이 PC에서 확인했다. Windows 11 x64, Python 3.13.9, Spotify 1.3.6.1921, Spicetify 2.46.3, ivLyrics 7.0.16을 기준으로 한다.

| 검증 | 결과 | 범위와 한계 |
| --- | --- | --- |
| 프로젝트 이동 | 원본 파일 11 개의 SHA-256 일치 | 원본 메타데이터와 이전 문서는 Git에서 제외한 work/migration에 보존 |
| Python 회귀 검사 | 43 개 통과, 건너뛴 검사 없음 | 기존 원문 대조와 캐시, 커버 후보 및 종료 조건 검사 유지 |
| JavaScript 회귀 검사 | 19 개 통과 | 발음 연결, 알림 제거와 하단 제목 복사 범위 검사 |
| 하단 제목 우클릭 | 실제 복사 일치 | 현재 곡 제목 27 글자와 복사 결과가 정확히 일치, 단일 곡 확인 |
| 일반 실행 환경의 바로가기 | 이전 0.4.2에서 실제 시작 확인 | Spotify와 도우미를 모두 종료한 상태, 단일 PC 확인 |
| 소스 배포 초안 | 허용 목록 기반 압축과 해시 생성 | 독립 실행 설치 프로그램이 아닌 소스 초안 |

하단 재생바의 제목은 곡 링크가 아니라 앨범 링크였다. 기존 곡 메뉴의 선택 URI 판정에 걸리지 않아 복사 항목이 나오지 않았다. 현재 버전은 확인한 재생 위젯 안에서 전체 현재 제목과 일치하는 링크의 우클릭만 처리해 즉시 복사한다. 가수명과 다른 영역의 우클릭에는 개입하지 않는다. Spotify의 화면 구조가 바뀌면 이 경로의 재검증이 필요하다.

여러 곡과 Spotify 업데이트 후의 화면 회귀 검사, 다른 PC의 설치와 제거, 전체 곡의 발음 청취 검수는 완료하지 않았다. 검사 통과를 사용자 검수 완료나 정식 배포 준비 완료로 해석하지 않는다. 이전 조회 성능 수치와 실패 사례는 로컬의 이전 기록에 유지한다.

## PC 커버곡 실제 재생 후속 검증

이전에 원문부터 No lyrics found로 끝났던 히노모리 시즈쿠의 밀크 크라운 온 소네치카 커버를 Spotify에서 실제 재생했다. ivLyrics 진입 후 자연스러운 곡 전환을 사용했으며 가사 캐시 삭제나 수동 다시 불러오기는 하지 않았다. 빠른 표시 설정은 제공자 우선, 선택형 자동 발음은 켜진 상태였다.

재생 요청을 시작한 뒤 약 2.36 초에 LyricsPlus의 원문 표시 데이터 73 줄이, 약 3.18 초에 한글 발음 73 줄이 확인됐다. 기존 발음 자료는 72/73 줄이 연결됐고 1 줄은 기기 내부 자동 발음으로 보완됐다. 도우미 응답의 캐시 표시는 거짓이었으며 실제 현재 화면의 문서 요소에서도 발음 문자열 1 줄의 존재를 확인했다. 원래 가사 화면의 가상 스크롤 등으로 현재 화면에 존재하는 줄과 전체 표시 데이터 수는 다르다.

이 결과는 한 곡의 단일 실제 재생 검증이며 전체 곡의 발음 청취 검수나 평균 성능 수치가 아니다. 가사 제공 서버가 곡마다 다르므로 모든 커버곡의 성공이나 같은 속도를 보장하지 않는다. 검증 후 원래 선택했던 곡과 재생 목록 및 일시정지 상태를 복원하고 임시 디버깅 옵션을 제거한다.

## 안드로이드 후속 검증

Myspoti 기준 커밋과 한글 패치에서 Java 엔진 검사 22 개가 모두 통과했다. Kotlin·Compose 컴파일, R8 최적화, release APK 생성과 서명 검증을 통과했다. applicationId는 app.myspoti.hangul이며 versionCode는 이전 1084에서 1085로 증가했다. 로컬 설치 후보의 서명자가 이전 개인 설치용 APK와 같음을 확인했다. 원본 IPADIC 고지가 APK 안에 유지되는 것도 확인했다.

휴대폰 없이 같은 Java 엔진을 PC의 JVM에서 실행하고 공개 문서에 연결했다. 기존 PC 진단에서 얻은 원문 입력을 사용했으며 원문 파일은 Git에서 제외했다. 캐시를 쓰지 않는 새 엔진에서 메서드 호출부터 반환까지 측정한 단일 조회다.

| 곡 | 연결된 일본어 줄 | 전체 입력·출력 줄 수 | 엔진 조회 시간 | 출처 |
| --- | --- | --- | --- | --- |
| 모니터링 | 85 / 85 | 90 / 90 | 약 1.04 초 | 나무위키 원제 문서 |
| Execution Clap | 57 / 60 | 67 / 67 | 약 1.86 초 | 나무위키 처형박수 문서 |

이 시간은 휴대폰 성능 측정이 아니다. 처형박수의 남은 3 줄은 기존 발음 자료 기준으로 미일치 상태를 유지했다. 선택형 자동 발음의 단위 검사는 별도로 통과했지만 이 두 조회에서는 자동으로 만든 발음을 성공 줄 수에 합산하지 않았다.

초기 검사에서 취소된 작업이 사전 초기화에 진입해 예외를 만들던 결함을 확인했고, 네트워크 응답 직후 취소를 확인하도록 바꾼 뒤 같은 회귀 검사를 통과했다. 휴대폰 설치, 계정 로그인, 실제 제목 길게 누르기와 음악 재생 및 Spotify Connect 전환 검증은 대기한다. 휴대폰 미검증 사실을 밝힌 베타 APK는 사용자 요청에 따라 안드로이드 전용 저장소에 배포한다. 이전의 로컬 전용 방침은 이 배포 방식으로 변경했다.

## 0.5.0 설치본 후속 검증

CPython 3.13.17 내장 배포와 고정된 의존성을 설치본에 포함했다. 빌드한 내장 Python에 격리 옵션을 적용하고 PATH를 Windows System32만 남긴 상태에서 사전 변환을 통과했다. 실제 설치 후에도 같은 PATH 조건에서 시작 스크립트를 실행했고, 상태 응답의 0.5.0 도우미가 선택한 설치 폴더의 runtime/pythonw.exe로 실행되는 것을 확인했다. 기존 전역 Python이 설치된 PC이므로 이 시험은 Python 미설치 PC의 시험과 구별한다.

EXE를 한글과 공백이 들어간 전용 폴더에 설치했고 종료 코드 0과 프로그램 제거 등록 및 인용부호가 있는 제거 명령을 확인했다. 제거 완료 후 기존 Spicetify 설정, 확장, 바탕화면 바로가기, cache.json과 aliases.json이 모두 설치 전 SHA-256과 일치했다. 설치 위치 등록도 제거됐다. 설치 준비의 폴더 경계와 프로세스 식별, 원본과 적용 상태의 백업 분기 검사 8 개를 Windows PowerShell 5.1에서 통과했다.

첫 실제 설치에서는 이미 적용된 Spicetify에 다시 backup을 요청해 실패했다. 원본 .spa가 있는 상태에서만 backup apply를 사용하고 이미 적용된 상태에서는 apply를 사용하도록 고쳤다. 그 뒤 같은 경로의 설치와 제거가 성공했다. 조용한 설치의 오류 대화상자는 기본 응답으로 종료하도록 바꾸고 오류 종료 코드를 명시했다. 폴더 선택 화면의 실제 클릭 검증과 깨끗한 다른 Windows PC에서의 설치는 남아 있다.
