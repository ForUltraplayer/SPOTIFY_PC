# PC 기능 확장판 배포 준비

2026년 10월 27일 기준으로 현재 개발판은 설치본 배포 전 준비 단계다. 공개 0.6.3과 개발 PC 적용본은 구분한다. 다음 제품 버전은 기능 범위를 고려해 0.7.0을 제안하며, 공개 버전과 설치 파일을 같은 이름으로 교체하지 않는다. 아래 차단 조건을 해소하고 동일한 설치 파일을 검증한 뒤 공개 후보로 판단한다.

같은 날 후속 작업으로 0.7.0 로컬 설치 후보를 준비했다. 아래 초기 계획의 미완료 표시는 당시 상태이며, 최신 구현과 검증 범위는 마지막의 후속 변경 절과 후보에 첨부한 검증 결과를 따른다.

## 용어

| 식별자 | 의미 |
| --- | --- |
| Setup.exe | 새 설치와 같은 폴더 덮어 설치를 수행하는 설치 프로그램 |
| Update.exe | 기존 설치 위치를 찾고 검증된 설치 프로그램을 실행하는 업데이트 실행기 |
| payload | 설치 프로그램이 소유하는 코드와 실행 도구의 파일 집합 |
| RC | 정식 배포 전 시험 후보 |
| SHA-256 | 배포 파일과 소스의 내용 일치를 확인하는 해시 |
| localStorage, IndexedDB | Spotify 안의 혼합 목록과 곡별 싱크 등 사용자 데이터를 저장하는 브라우저 저장소 |

## 배포 구성

사용자는 설치 EXE 하나로 필요한 실행 도구를 구성하고 설치 폴더를 선택한다. 대상 PC에 Python이나 Node를 별도로 설치하도록 요구하지 않는다. 개발용 시작 스크립트와 개발 PC의 도구를 재사용하지 않아야 한다. Windows 11 x64를 첫 검증 대상으로 삼고 Windows 10과 ARM64는 검증 전까지 지원 완료로 표시하지 않는다.

| 구성 | 배포 방식 | 현재 준비 상태 |
| --- | --- | --- |
| Spotify와 SpotX 및 Spicetify | 기존 통합 설치 경로 유지, 검증한 공식 Spotify 파일은 설치 때 다운로드 | 기존 0.6.3 경로 존재, 신규 확장 조합 재검증 필요 |
| 발음 도우미와 ivLyrics | 내장 Python과 고정한 ivLyrics 원본에 자체 변환을 적용해 동봉 | 소스 검사 통과, 새 EXE 설치 검증 필요 |
| YouTube 혼합 목록과 ivLyrics 연결 | 정식 확장에서 모듈 로딩, 설치 폴더의 도우미가 제공 | 개발용 로더에만 연결된 부분 정리 필요 |
| 임베드 제한 영상의 공개 오디오 대체 | yt-dlp와 선택한 JavaScript 실행기 및 필요한 부속 자산을 설치 폴더에 동봉 | 버전과 해시 및 고지와 대응 소스 고정 필요 |
| 쉽게 싱크 맞추기 | ivLyrics 원본 세 파일에 검증한 변환 적용 | 기존 DB를 사용한 실제 UI 저장과 취소 확인 |
| 별도 Windows 가사 오버레이 | 배포 허락이 확인된 구성만 설치 옵션으로 제공 | 수정본 배포 권한 미확인으로 차단 |

외부 데스크톱 오버레이는 현재 [원본 저장소](https://github.com/ivLis-Studio/ivLyrics-overlay)의 GitHub 라이선스 메타데이터가 비어 있고, 로컬 소스 검사에서도 배포 허락을 확인하지 못했다. 이 상태에서 수정 EXE와 파생 소스를 배포 대상으로 확정하지 않는다. 비공개 저장소, 사용자의 원본 설치 또는 패치 파일 배포가 그 자체로 허락을 대신하지 않는다. 허락을 확보하거나 배포 가능한 대안이 준비되면 포함한다. 해결 전 공개 후보에서는 해당 외부 앱의 수정 기능을 제외하고 그 범위를 명시한다. 원본 작성자에게 연락하는 작업은 별도 요청 없이 수행하지 않는다.

## 후보와 정식판 분리

후보는 프로젝트 작업 폴더의 배포 준비 영역에서 만들고 기존 dist에는 쓰지 않는다. 별도의 빌드 식별자와 SHA-256을 기록한다. 제품 버전과 Windows 파일 버전은 기존 숫자 세 자리 계약을 유지하고 후보 차수는 경로와 빌드 기록에 둔다. 공개 전 제품 버전 변경은 확장, 도우미, 설치 상태, 소스 압축과 업데이트 자산 이름을 함께 검증한다.

기존 자동 업데이터는 GitHub의 prerelease 필드를 확인하지 않았다. 따라서 v0.7.0 같은 숫자 태그를 시험 릴리스로 공개하는 방식은 구버전 사용자에게 안전하지 않다. 이번 수정본은 시험 릴리스를 제외하지만 이미 배포된 사용자 코드에는 즉시 반영되지 않는다. 검증 중에는 로컬 후보 또는 접근이 제한된 배포를 사용한다. 공개 시험이 필요하면 기존 숫자 태그 정규식에 맞지 않는 RC 태그와 후보용 자산 이름을 사용하고 구버전 업데이터로 선택 불가를 검사한다. 정식 숫자 태그는 실제 공개 승인이 난 뒤 사용한다.

Setup과 Update는 서로 다른 설치 로직을 갖지 않는다. 업데이트 실행기는 기존 위치를 찾아 동일한 설치 엔진에 넘긴다. 0.6.0은 자동 업데이트의 시작 경로가 없을 수 있으므로 수동 Update 진입을 검증하고, 0.6.1과 0.6.3은 수동 및 예약된 업데이트를 모두 검증한다. 중간 버전을 차례로 설치하도록 요구하지 않는 구성을 목표로 한다. 이는 새 후보에서 아직 확인해야 할 목표다.

## 구성 요소 고정과 갱신

현재 구성 요소 목록(components.json)은 Spotify 1.3.6.1921, Spicetify 2.46.4, ivLyrics 7.0.16, SpotX 기준 커밋, Python 3.13.17 및 NSIS 3.13을 관리한다. 대체 재생 도구와 외부 오버레이를 채택하면 같은 목록에 실제 버전, 다운로드 주소, 해시, 크기, 라이선스 고지와 대응 소스 정보를 추가한다. 오버레이는 권한 문제를 해소한 뒤 추가한다.

원본 업데이트 감지는 후보를 알리는 역할이며 사용자 실행본을 바로 교체하지 않는다. 다운로드 고정과 어댑터 계약 검사, 후보 설치 및 실제 재생 검증을 거쳐 자체 앱의 다음 배포 묶음으로 반영한다. 외부 오버레이 자체 업데이트가 로컬 수정본을 원본으로 덮는 경로도 배포 구성에 맞춰 처리해야 한다.

패키지에서 실행 도구를 찾을 때 시스템 PATH에 있는 임의 버전을 대신 사용하지 않는다. 개발 환경의 대체 경로가 필요하면 명시적인 개발 모드로 제한한다. 다른 PC에 없는 실행 도구가 필요할 경우 기능 안내에 설치 요구를 숨기지 않는다.

## 사용자 데이터와 실패 복원

설치 코드와 사용자 데이터를 구분한다. 로그인 프로필, 발음 캐시와 별칭, 혼합 목록과 순서, 가사 검색 정보, 곡별 싱크와 오버레이 설정은 새 코드로 덮어쓰지 않는다. 브라우저 저장소는 원점과 프로필이 유지돼야 하며 설치 폴더 백업만으로 보존이 끝났다고 판단하지 않는다.

| 데이터 | 현재 저장 계약 | 전환 검증 |
| --- | --- | --- |
| 혼합 목록과 순서 및 검색 정보 | Spotify의 localStorage, 목록 JSON 입출력 | 원본 목록과 YouTube 목록 및 중복 항목 순서 전후 비교 |
| 곡별 싱크 | ivLyrics-db의 track-sync-offsets, Spotify 또는 YouTube 식별자 | ±60 초와 YouTube 키 보존, 원래 표시 제목 유지 |
| 발음 캐시와 별칭 | 기존 도우미 사용자 데이터 | 앱 파일 교체와 제거 시 보존 |
| 목록 내보내기 | 기존 도우미의 exports 폴더 | 원본 곡과 링크 및 순서 복원, 시크릿과 만료 스트림 주소 제외 |
| 별도 오버레이 설정 | 기존 앱의 브라우저 및 네이티브 설정 | 포함하는 경우 표시 방식과 크기 및 투명도 보존 |

현재 혼합 목록 JSON은 곡별 싱크 DB 전체의 백업을 대신하지 않는다. 사용자 데이터 내보내기와 복원 범위를 구분하고, 원본 ivLyrics 백업 정규화가 YouTube 키와 큰 보정값을 유지하는지 확인한다. 구버전은 ±10 초 제한과 다른 키 규칙을 가질 수 있으므로 새 데이터를 그대로 둔 채 구버전을 실행해도 안전하다고 가정하지 않는다.

설치 변경은 임시 준비, 무결성 검사, 이전 소유 파일과 데이터 보호 기록, 새 파일 적용, 통합 확인, 설치 상태 확정 순서로 구성한다. 실패하면 코드와 runtime 및 통합 상태를 같은 버전으로 되돌린다. 새 파일 목록에서 빠진 이전 소유 파일도 구분해 처리한다. 전원 중단에 대비한 복구 기록은 교체 대상 파일과 분리해야 한다. 현재 설치기는 앱 파일을 먼저 덮은 뒤 통합을 수행하므로 이 전체 복원을 아직 제공하지 않는다.

도우미의 준비 응답에는 실행본과 기능 계약을 식별할 정보가 필요하다. 설치 경로와 소유 프로세스, 버전, 프로토콜 및 필요한 기능을 대조해 개발판이나 다른 설치본을 재사용하지 않게 한다. 기존 포트가 다른 소유자에게 점유됐을 때는 임의 종료하지 않고 충돌을 안내한다. 새 프로토콜과 전환 처리는 구현 후 실제 설치본에서 확인한다.

## 필수 설치 검증

| 시나리오 | 환경 | 통과 기준 |
| --- | --- | --- |
| 새 설치 | Python과 yt-dlp 및 Deno와 Node가 없는 Windows 사용자 환경 | 일반 바로가기에서 로그인과 재생 및 기능 진입 |
| 0.6.0에서 전환 | 같은 설치 위치, 사용자 데이터 포함 | 수동 Update 한 번으로 직접 전환, 데이터 유지 |
| 0.6.1에서 전환 | 같은 위치, 대기 중 업데이트 포함 | 수동 및 예약 업데이트의 무결성 확인과 전환 |
| 0.6.3에서 전환 | 실제 이전 설치본과 데이터 | 새 기능과 기존 가사 기능 동작, 실패 복원 |
| 사용자 지정 위치 | 한글과 공백 및 기본 위치 밖의 폴더 | 설치와 실행 및 제거, 데이터 보존 |
| 오류 주입 | 다운로드 실패, 해시 불일치, 통합 실패, 설치 중단 | 실행 차단과 오류 원문, 이전 실행본 복구 |
| 실행 충돌 | 개발 도우미, 다른 설치 도우미, 두 Spotify 실행 | 잘못된 도우미 재사용과 다른 앱 임의 종료 방지 |
| 실제 재생 | Spotify와 YouTube가 섞인 같은 목록 | 이전과 다음, 일시정지와 탐색, 순서와 썸네일 및 가사 연결 |
| 싱크와 설정 | Spotify 및 커버 영상, 오버레이 포함 시 별도 앱 | 곡별 보정 저장과 재시작 복원, 버튼 외형 보존 |

깨끗한 환경 시험은 개발판의 Spotify와 도우미를 모두 종료한 별도 사용자 또는 가상 머신에서 수행한다. PATH에서 도구를 빼는 검사는 보조 검사이며 실제 깨끗한 설치 검증을 대신하지 않는다. 검증용 재생은 사용자가 로그인한 후 공개 영상과 플레이리스트로 수행한다.

자동 검사의 소스 지문과 구성 요소 해시, 설치 파일 해시, 실행 환경, 성공과 실패 로그 및 복원 결과를 묶어 기록한다. 필수 UI 검사는 의존성이 없다고 생략한 채 통과시키지 않는다. Windows의 심볼릭 링크 권한처럼 환경상 생략된 항목은 별도로 남긴다. 소스 테스트 성공을 실제 EXE 설치 성공으로 표시하지 않는다.

## 이번에 반영한 배포 보호

1. 안정 업데이터가 GitHub 시험 릴리스를 제외하고 RC 태그도 거절하도록 회귀 검사를 추가했다. 기존 사용자에게는 새 코드가 설치된 이후 적용된다.
2. 빌더가 대응 소스 ZIP의 파일 목록과 manifest 및 실제 바이트를 현재 체크아웃과 대조한다. 오래된 소스, 바뀐 바이트, 빠진 파일과 중복 및 추가 파일을 거절한다.
3. UI 검사용 React와 렌더러를 프로젝트 전용 잠금 파일로 고정했다. 호환성 검사 자체가 UI 실행을 필수로 요구하고 빌더도 해당 조건을 확인한다. CI는 해당 도구를 설치하며 필수 UI 검사가 실행되지 않으면 실패한다. 테스트 의존성은 최종 사용자 실행 도구에 포함하지 않는다.
4. 소스 압축과 설치 빌더에 별도 출력 폴더를 지정할 수 있게 했고, 같은 이름의 산출물이 있으면 덮어쓰기를 거절한다. 설치 빌더의 대응 소스 경로도 후보에 맞춰 지정할 수 있다.

출력 폴더 분리는 다음처럼 사용한다. 후보 경로는 새 빈 폴더를 선택하고, 실제 버전은 빌드 전 함께 확정한다. 아래 명령을 실행했다고 해서 설치 검증이나 공개 판단이 완료되는 것은 아니다.

```powershell
npm ci --ignore-scripts --prefix tests/ui
$env:IVLYRICS_REQUIRE_UI_TESTS = '1'
python scripts/check_compatibility.py
python scripts/prepare_release.py --output-dir work/release-candidates/candidate-1
python scripts/build_installer.py --output-dir work/release-candidates/candidate-1
```

## 준비 순서와 완료 기준

먼저 공개 0.6.3의 파일 해시와 개발 소스를 보존하고 후보 출력을 분리한다. 다음으로 외부 오버레이의 포함 여부와 실행 도구 고정을 정한 뒤 정식 시작 경로와 도우미 식별 및 전체 복원을 구현한다. 그 다음 설치 행렬을 통과한 같은 해시의 후보로 제한 시험을 진행한다. 마지막으로 README의 기존 형식과 릴리스 설명, 라이선스 고지 및 대응 소스를 확인해 공개 판단 자료를 준비한다.

최종 제공물은 선택한 제품 버전의 Setup.exe, Update.exe, 대응 소스 ZIP, SHA-256 목록과 설치 및 복원 검증 기록이다. 실제 자산 이름과 내부 버전의 일치가 확인돼야 한다. 코드 서명은 현재 적용되지 않았으며 서명 여부와 Windows 경고는 배포 안내에 정확히 표시한다. Android는 별도 저장소와 APK 서명 및 패키지 계약을 유지하고 이번 PC 후보에 섞지 않는다.

이 계획의 차단 조건이 남아 있는 동안 공개 준비 완료로 바꾸지 않는다. 작성일 당시 전체 설치본 검증과 전체 파일 복원, 정식 YouTube 시작 경로와 대체 도구 동봉 및 외부 오버레이의 권한 문제는 미완료다.

## 2026년 10월 27일 후속 변경

로컬 후보의 버전은 0.7.0으로 정했다. 정식 시작 스크립트에서 YouTube 기능을 불러오며 설치 폴더의 Python과 Node 및 yt-dlp와 부속 해석기를 사용한다. 도우미의 경로와 버전 및 기능 계약이 다른 실행 인스턴스는 재사용하지 않는다. 현재 소스와 대응 소스 ZIP 및 구성 요소 해시가 호환성 검사 결과와 일치해야 설치본을 빌드할 수 있다.

전체 폴더 복원은 별도 설치 기록을 사용하는 파일 교체 절차로 구현했다. 임시 압축 해제와 무결성 검사 후 이전 폴더를 검증해 보존하고, 통합 처리와 설치 등록 및 바로가기 생성이 완료된 뒤에만 확정한다. 실패 시에는 코드와 runtime 및 Spotify 화면과 설정뿐 아니라 설치 등록과 바로가기를 복원한다. 중단 기록은 다음 설치 실행에서 복구한다. 같은 데스크톱 세션의 설치와 제거를 직렬화하며 프로세스 종료는 해당 설치 경로와 정확한 도우미 인수를 확인한 대상에 한정한다.

실제 작업 폴더 점유 검사에서 구버전 업데이터의 부모 프로세스가 폴더 이동을 막는 조건을 확인했다. 폴더 교체가 불가능하면 검증한 백업으로 파일을 제자리에 복원하는 경로를 추가했다. 원본 백업을 유지하고 중단 후 재시도하며, 진단 자료는 변경 파일만 별도로 보관한다. 새 시작 스크립트와 업데이터는 설치를 기다리는 동안 작업 폴더를 놓아준다. 구버전 부모에는 이 변경을 소급 적용할 수 없어 실제 설치 행렬에서도 별도 프로세스로 설치 폴더를 점유한 상태의 복원을 검사한다.

기존 Tauri 오버레이는 원본 UI와 설정 식별자를 유지한 로컬 수정본을 포함한다. 별도 WPF 시제품은 포함하지 않는다. 기존 재생 조작과 외형 수정에 창 위치 조절을 추가했으며 바이너리와 대응 소스 및 수정 패치를 해시로 고정했다. 원본의 재배포 라이선스 미확인 상태는 유지한다. 따라서 빌더는 이 구성의 출력을 프로젝트 work 아래로 제한하고 공개 준비 상태를 거부한다. 로컬 후보를 만드는 승인과 외부 공개를 구분한다.

같은 날 후속 화면 피드백에서 겹침 대상은 창의 외부 위치가 아니라 발음과 하단 재생 버튼인 것으로 확인했다. 버튼을 창 하단의 고정 좌표에 겹쳐 그리던 방식에서 가사와 분리한 하단 영역으로 바꿨다. 간격과 창 높이를 조절할 수 있게 하며 긴 가사는 가사 영역 안에서 스크롤한다. 창 위치 조절은 부가 기능으로 유지하고, 해당 기능만으로 겹침을 해결했다고 판단하지 않는다.

구버전 전환 검사는 0.6.0과 0.6.1 및 0.6.3의 배포 EXE를 기준으로 한다. 직접 Setup 전환과 기존 자동 업데이터의 새 버전 선택 및 적용을 구분한다. 아직 공개되지 않은 후보의 릴리스 정보와 다운로드만 로컬에서 공급하며, 설치에는 실제 후보 EXE를 사용한다. 별도 Windows 계정이나 깨끗한 가상 머신 검증을 대신하는 시험으로 설명하지 않는다. 실측 결과와 동일 EXE의 해시는 로컬 후보와 함께 보관한다.

### 2026년 10월 27일 버튼 위치 조절 범위 정정

사용자 검토에서 창 높이 늘리기는 되돌리기가 없고 마우스로 이동은 기존 동작 탭의 잠금 해제와 중복되는 것으로 확인했다. 앞 절의 창 위치 및 높이 조절 계획은 적용 범위가 지나쳤다. 해당 설정 섹션과 버튼을 제거하고 기존 레이아웃 탭에 재생 버튼 세로 위치 슬라이더 하나만 둔다. 기존 간격 저장값을 재사용하며 창 크기와 위치 및 잠금은 변경하지 않는다. 가사 다음의 별도 영역에 버튼을 배치해 겹침을 방지하고, 공간이 충분할 때 슬라이더 값만큼 실제 버튼이 아래로 이동한다. 창 높이가 부족하면 가사 영역의 스크롤을 사용하며 모든 가사를 동시에 표시하지는 않는다. 앞선 판단과 변경 이력은 보존하고 이 절을 현재 설계로 적용한다.

## 0.7.4 후보 (제안)

사용자가 요청한 항목이며 아직 구현하지 않았다.

- 설치된 버전 확인. 지금은 Windows 설정의 앱 목록에서만 볼 수 있다.
- 수동 업데이트 확인. 지금은 바로가기 실행 때 일정 간격으로만 확인하고, 업데이트 적용은 다음 실행 때 한다.

위치 제안은 Spotify 오른쪽 위 프로필 메뉴에 「Spotify 한글 가사 (버전)」 항목을 두는 것이다. 사용자가 항상 여는 화면이 Spotify 창이고, 확장(`hangul-lyrics.js`), YouTube 모듈, 도우미 버전이 모두 이 창에서 모인다. 항목을 누르면 설치본, 도우미, 확장 버전을 함께 보여 주고 업데이트 확인을 실행한다. 확인은 도우미가 `auto-update.ps1 -Mode Check`를 간격 무시로 실행하는 방식을 검토한다. 설치는 Spotify가 꺼져 있어야 하므로 「다음 실행 때 적용」 안내로 끝낸다. 데스크톱 가사창과 안드로이드판은 각자 버전 체계가 달라 이 메뉴에 넣지 않는다.
