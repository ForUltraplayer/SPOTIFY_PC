# PC 링크 음악 개발 검증

## 범위

이 기능은 작업 중인 개발 코드이며 공개 0.6.3 설치본과 구분한다. YouTube와 YouTube Music의 개별 영상 주소를 저장하고 Spotify 창 안의 표준 YouTube 플레이어에서 스트리밍한다. 음원 파일은 저장하지 않는다. 일반적인 스트리밍 버퍼와 브라우저 캐시는 사용할 수 있다.

기존 Spotify 플레이리스트 화면에서 YouTube 링크를 추가하고 Spotify 곡들과 같은 표에서 재생한다. 플레이리스트 제목과 이미지, 사이드바를 유지하며 통합 곡 표와 오른쪽 재생 영역을 연결한다. Spotify 서버에 있는 원본 재생목록에 YouTube 항목을 쓰는 기능은 제공하지 않는다. 링크와 삽입 위치는 플레이리스트 ID에 연결해 이 PC의 Spotify 브라우저 저장소에 남기며 계정의 다른 PC로 자동 동기화하지 않는다. 원본 Spotify 곡 목록은 화면을 열거나 다시 불러올 때 읽는다.

## 사용

현재 개발 PC에서는 프로젝트 폴더에서 아래 명령으로 시작한다. Spotify 재시작이 필요 없는 경우에는 마지막 인수를 생략한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_youtube_dev.ps1 -Restart
```

Spotify에서 플레이리스트를 열고 제목 아래의 YouTube 링크 추가를 누른다. 영상 주소와 삽입 위치를 고른 뒤 이 플레이리스트에 추가를 누른다. 이전 개발 화면에서 저장한 YouTube 링크도 선택할 수 있다. 목록 앞이나 끝, 특정 Spotify 곡 뒤에 넣을 수 있다. 통합 표에서 YouTube 곡의 위아래 버튼이나 끌어놓기로 위치를 바꾸며 링크 제거는 이 PC에 저장된 항목에만 적용한다. 곡의 재생 버튼과 더블클릭, 플레이리스트의 큰 재생 버튼으로 혼합 재생을 시작한다. 재생 도중 순서를 바꾼 내용은 목록을 다시 재생할 때 적용한다.

YouTube 재생 중에는 오른쪽 지금 재생 중 영역에 표준 영상 플레이어를 표시하고 기존 하단 재생바의 재생과 일시정지, 이전과 다음, 탐색, 볼륨과 음소거를 연결한다. 오른쪽 영역이 닫혀 있으면 작은 재생 화면을 유지한다. 셔플과 반복은 혼합 목록에 적용한다. 재생 종료를 누르면 혼합 재생을 시작하기 전의 Spotify 곡과 목록, 위치 및 일시정지 상태를 복원한다.

현재 통합 표에서는 Spotify와 YouTube 항목 모두 위아래 버튼과 끌어놓기로 순서를 바꾼다. 이 순서는 로컬에 저장하고 Spotify 순서로 버튼으로 초기화한다. 원본 Spotify 서버의 순서를 바꾸는 작업은 아니다. 새 원본 곡은 저장된 로컬 순서의 뒤에 합치고, 원본에서 삭제한 곡은 통합 표에서 제외한다.

원본 편집을 누르면 Spotify의 원래 곡 표가 다시 나타난다. 원본 Spotify 곡의 추가와 삭제 및 기본 목록 검색은 원본 화면에서 처리한다. 편집 후 통합 목록으로 돌아오면 원본을 다시 읽는다. 같은 Spotify 곡이 반복되는 목록은 각 항목의 고유 ID로 위치를 구분한다. 연결한 Spotify 항목이 삭제되면 해당 YouTube 링크는 목록 끝에 남는다. 현재 최대 2,000 곡이며 지원하지 않는 항목이나 조회 오류가 있으면 원본 곡 표를 유지한다.

혼합 재생은 이 컴퓨터에서 지원한다. Spotify가 다른 Connect 기기에 연결되어 있으면 기기에 연결하기에서 이 컴퓨터를 먼저 선택한다. 다른 기기로 YouTube 오디오를 보내거나 계정 전체의 재생 대기열을 YouTube 항목으로 바꾸는 기능은 제공하지 않는다.

## 기존 ivLyrics와 오버레이

오른쪽 ivLyrics 가사 버튼이나 기존 마이크 버튼으로 ivLyrics를 연다. YouTube에는 youtube:video:영상ID라는 별도 곡 식별자를 사용한다. ivLyrics의 곡 정보와 재생 시간, 검색 제공자와 발음 캐시 경계를 연결하고 실제 Spotify backend의 곡 데이터를 덮어쓰지 않는다. Spotify 곡으로 전환하면 기본 가사 경로로 복귀한다. 원문은 공개 LRCLIB에서 조회하고 한글 발음은 기존 한글 가사 제공자를 사용한다. 자동 발음 사용 여부 등 기존 사용자 설정은 유지한다.

검색용 원곡명이 영상 제목에서 드러나지 않으면 가사 검색 정보에서 원곡 제목과 가수를 지정한다. 원곡의 가사 시간은 커버 영상과 다를 수 있다. LRCLIB의 429, 5xx와 일시 네트워크 실패는 2 초 간격으로 최대 3 회 추가 시도하며 전체 20 초 제한을 공유한다. 곡이나 검색 정보가 바뀌면 이전 요청을 취소하고 실패는 캐시하지 않는다.

Spotify 내부의 ivLyrics 전체 화면 가사 오버레이에서 기본 컨트롤이 보이면 재사용하고, 숨겨져 있으면 이전 곡과 재생 또는 일시정지 및 다음 곡 버튼을 표시한다. 포커스한 버튼의 Space 및 Enter는 기본 버튼 동작을 유지한다. 별도 OS 오버레이 프로그램의 UI와 localhost:15000 수신 앱은 이번 변경의 적용 대상으로 검증하지 않았다.

## 파일 내보내기와 가져오기

통합 표에서 내보내기를 누르면 Spotify 곡 스냅샷과 YouTube 링크, 혼합 순서 및 가사 검색 정보를 JSON 한 파일에 저장한다. 저장 위치는 앱 상태 폴더의 exports이며 완료 창에 실제 경로와 경로 복사 버튼을 표시한다. 임의의 파일 경로를 입력받지 않는다. 파일에는 음원, 로그인 토큰이나 만료되는 직접 스트림 URL을 넣지 않는다.

가져오기는 3 MB 이하의 해당 JSON 파일을 읽고 기존 목록을 덮어쓰지 않는 새 로컬 목록을 만든다. 원본 Spotify 목록에 접근하지 못해도 파일에 담긴 Spotify 곡 스냅샷과 YouTube 항목을 표시하고 곡 URI로 재생한다. 프로필 메뉴의 로컬 혼합 플레이리스트에서 다시 열 수 있다. 원본 Spotify 목록에 대한 쓰기 API는 사용하지 않는다. 이 로컬 목록에는 원본 편집이 적용되지 않는다.

## 재생과 음질

YouTube 음원에는 Spotify의 오디오 품질 설정이 적용되지 않는다. 표준 YouTube 플레이어가 네트워크와 영상 소스에 따라 품질을 선택하며 영상 품질 표시는 오디오 비트레이트 측정값이 아니다. 외부 임베드 제한에는 아래 공개 오디오 대체 경로를 사용하고, 비공개와 삭제 및 네트워크 오류는 실패로 표시한다. 표준 플레이어의 광고나 계정 상태를 조작하지 않는다.

현재 링크 처리는 youtube.com과 music.youtube.com의 같은 영상 ID를 같은 플레이어로 보낸다. Music 도메인을 넣는 것만으로 Music Premium의 고음질 설정이 전달되지는 않는다. YouTube Music 자체의 고음질 설명은 공식 도움말에서 최대 256 kbps AAC 및 Opus로 안내하지만 이 확장의 품질 보장이 아니다. [YouTube Music 음질 도움말](https://support.google.com/youtubemusic/answer/9076559)

표준 임베드에서 101 또는 150 외부 재생 제한이 발생하면 설치된 yt-dlp와 JavaScript 실행기로 공개 Opus 오디오 주소를 확인해 대체 스트리밍한다. 로그인이 필요한 영상과 연령 제한 및 DRM은 처리하지 않는다. 주소는 메모리에 최대 5 분 재사용하고 파일로 저장하지 않는다. 재생 참조가 만료되거나 네트워크 재생 오류가 발생하면 해당 곡을 다시 시작해 갱신한다. 일시 조회 실패는 2 초 간격 최대 3 회 추가 시도한다. 추출은 동시 1 건, 요청당 최대 45 초이며 시간 초과 시 소유 프로세스 트리를 종료한다.

이 대체 경로는 현재 개발 PC에 설치된 yt-dlp 및 Deno 또는 Node를 사용한다. 해당 실행기들을 포함한 설치 EXE는 이번 작업에서 만들거나 배포하지 않았다. 배포 전에는 실행기 버전, 라이선스 및 업데이트 검사를 배포 구성 요소에 포함해야 한다. 일반 표준 플레이어 경로와 가사 기능은 이 추출기를 필요로 하지 않는다.

## 구성과 수명

기존 발음 도우미의 루프백 주소 127.0.0.1:19643에서 재생 프레임과 공개 영상 메타데이터를 제공한다. 새 운영 서비스나 부팅 자동 시작은 등록하지 않는다. 개발 실행 스크립트도 기존 도우미의 Spotify 종료 감지를 사용한다. Spotify가 사라진 뒤 감지 간격과 유휴 대기 시간을 거쳐 종료한다.

ivLyrics가 전역 YouTube 객체를 변경하므로 직접 같은 객체를 쓰는 시험은 초기화가 완료되지 않았다. 별도 프레임에서 표준 플레이어를 초기화하는 대안을 시험해 실제 재생에 성공했다. 재생 상태 메시지는 Spotify 출처, 해당 프레임과 세션 식별자를 확인한다. 메타데이터 조회는 검증한 영상 ID로 고정된 YouTube 주소만 요청한다. 가사 검색은 유료 API를 사용하지 않는다.

개발 실행 스크립트는 실제 사용 중인 한글 확장에 로컬 개발 로더를 추가한다. 원본과 해시 및 수정 시각은 Git에서 제외한 work/youtube-development/loader-backup.json과 같은 폴더의 백업에 보존한다. 이후 Spicetify 재적용은 이 개발 로더를 없앨 수 있다. 복원할 때는 Spotify를 종료하고 기록된 백업을 해당 확장 경로에 복사한다. 도우미 중지는 기록된 PID가 이 프로젝트 bridge.py인지 확인한 뒤 종료한다.

## 검증과 한계

예시 영상 rKQptWhAvO0에서 실제 재생과 시간 증가, 음소거 해제 상태를 확인했다. 기존 하단 버튼으로 일시정지하고 Spotify 곡으로 전환한 다음 이전 버튼으로 YouTube에 복귀했다. 기존 Spotify 목록 27 곡을 별도 링크 목록으로 읽었으며 원본 목록 쓰기 API는 사용하지 않았다. 원곡 제목 東京テディベア와 가수 Neru로 가사 36 줄과 기존 한글 발음 자료를 조회했다. 커버 영상의 청취 검수와 원곡 시간의 정확한 일치는 완료하지 않았다.

하단 탐색 막대의 포인터 입력으로 YouTube 재생 위치가 바뀌었으며, 영상의 실제 종료 이벤트 뒤 목록의 Spotify 곡이 재생됐다. 시험 후 원래 Spotify 목록과 곡, 재생 위치 및 일시정지 상태를 복원했다. 진단 포트를 닫고 일반 Spotify를 재시작한 뒤 링크 음악 버튼과 저장된 YouTube 및 Spotify 항목이 다시 표시되는지 확인했다. 관련 회귀 검사 165 건은 통과했으며 새 기능을 포함한 설치 EXE의 실제 설치 검증은 아직 수행하지 않았다.

Spotify Connect와 다른 기기 재생, Spotify 원본 목록에 대한 외부 링크 삽입, YouTube 재생목록 주소 전체 가져오기는 이번 개별 영상 시험에서 확인하지 않았다. 상세 실행 기록과 현재 프로세스 상태 및 중지 방법은 work/runtime/RUNNING.md에 남긴다.

후속 목록 통합에서는 실제 Spotify 플레이리스트 화면에 원본 27 곡과 예시 YouTube 영상 1 곡이 같은 표로 나타나는 것을 확인했다. 해당 행의 재생 동작 뒤 영상 재생 상태와 시간, 하단 제목 및 오른쪽 지금 재생 중 영역을 확인했다. 원본 곡 사이 배치, 중복 곡의 개별 삽입 위치, 원본 순서 변경 반영, 연결 항목 삭제 후 보존, 로딩 준비 조건에 대한 회귀 검사를 추가했다. 초기 로딩 시 남아 있던 UI 중복은 재생 영역과 라우터 준비 이후 초기화하도록 수정했으며 깨끗한 렌더러 재로딩에서 컨트롤러와 재생 패널이 각각 하나임을 확인했다.

그 뒤 사용자가 개발 PC에서 직접 새 목록과 링크 재생을 시험 중이라고 확인했다. 이후 재생을 중단하거나 강제로 재시작하지 않았다. 마지막에 저장한 스크롤 재생 버튼 연결, 원격 기기 상태 안내와 목록 조회 시간 제한은 기존 실행 인스턴스를 바꾸지 않고 다음 실행에 적용한다. 이 마지막 수정본의 실제 GUI 재검증과 통합 화면에서의 영상 종료 후 전환 반복 검증은 아직 완료하지 않았다. 초기 분리 목록의 종료 전환 성공을 통합 화면의 최종 검증으로 대신하지 않는다.

최종 소스의 회귀 검사 170 건은 통과했다. 런타임 검증 기록과 자동 검사 보고서는 구분하며, 자동 검사 보고서의 runtime_playback 항목은 pending을 유지한다.

후속 실제 검증에서는 rKQptWhAvO0의 원문 36 줄과 한글 발음 표시를 기존 ivLyrics에서 확인했다. 전체 화면 오버레이의 일시정지, 다음 Spotify 곡과 이전 YouTube 곡 복귀도 확인했다. 제한 영상 _-uHa5KiR90는 표준 임베드 실패 후 직접 Opus 스트리밍으로 전환됐으며, 제공 메타데이터의 평균 비트레이트는 약 136 kbps다. 이는 실제 수신 비트레이트 측정값이 아니다. AAC는 이 Spotify 내 브라우저의 canPlayType 검사에서 지원하지 않았고 Opus는 지원했다.

피날레 제목만 조회하면 실제 LRCLIB가 503을 반환했으며, 원곡 가수 eill 지정 뒤 재조회에서 원문 41 줄과 발음 35 줄을 표시했다. 도우미는 일본어 35 줄 중 저자가 작성한 자료 33 줄을 매칭했고 나머지는 기존 자동 발음 설정을 따랐다. 시간 및 청취 일치를 검수 완료한 것으로 간주하지 않는다.

원본 Spotify 3 곡과 YouTube 3 곡을 실제 파일로 내보내고 새 로컬 목록으로 다시 가져왔다. 그 목록에서 Spotify 곡을 위로 이동하고 추가 제한 영상을 시험했다. 이 과정 전후 원본 Spotify 목록의 URI 및 항목 ID 순서는 동일했다. Windows 패키지 가상화로 서로 다른 문자열 경로가 같은 디렉터리를 가리키는 사례는 디렉터리 ID 비교로 복구했고, 실제 저장 파일을 다시 읽어 확인했다.

마지막 수정까지 저장한 뒤 진단 포트 없이 일반 Spotify를 다시 실행했다. 실제 UI에서 로컬 목록을 열어 Spotify 3 곡과 YouTube 4 곡 및 변경 순서가 유지됨을 확인했다. 제한 영상의 행을 클릭하면 공개 Opus 대체 재생으로 전환되고, ivLyrics 가사 버튼으로 기존 가사와 한글 발음이 나타나는 것을 확인했다. 종료 시에는 52 초에서 일시정지했다. 포트 9227 및 19644는 닫혔고 기존 기능 도우미의 루프백 포트 19643만 유지했다.

최신 자동 검사는 247 건 중 246 건이 통과했고, 심볼릭 링크 생성 권한이 필요한 1 건은 생략했다. 추출기의 시간 초과에서는 소유한 Python 부모와 자식 프로세스를 실제로 만들어 자식 종료를 확인했다. 소스 미리보기 압축을 작업 폴더에서 생성해 런타임 모듈 7 개가 모두 들어 있는지 확인했으며 공개 설치 파일은 교체하지 않았다.

## 재생목록과 실제 데스크톱 오버레이 후속 수정

앞선 전체 화면 오버레이 검증은 Spotify 내부 화면에 해당한다. 별도 Windows 가사 앱에 재생 버튼을 넣어 달라는 요청을 충족한 검증으로 볼 수 없어, 후속 작업에서 실제 데스크톱 앱도 수정했다. 대상 원본은 [ivLyrics-overlay](https://github.com/ivLis-Studio/ivLyrics-overlay)의 1.2.11 버전이다.

재생 프레임을 React가 관리하는 오른쪽 패널로 옮기면 탐색 과정에서 영상이 초기화될 수 있었다. 이제 프레임의 문서 내 위치를 유지하고 오른쪽 패널의 좌표에 맞춰 표시한다. 재생목록 버튼은 현재 혼합 목록을 열며, 목록의 재생 버튼은 같은 곡을 일시정지하거나 재개한다. 프레임이 다시 준비되는 경우에도 부모가 보관한 위치와 재생 의도로 한 번만 복원한다.

기존 마이크 버튼은 별도 가사 버튼 없이 현재 YouTube 곡의 ivLyrics를 연다. Spicetify가 형제 버튼의 클래스를 복사하면서 마이크에도 전체 화면 클래스가 붙는 사례가 실제 실행에서 확인됐다. 따라서 클래스만으로 구분하지 않고 기존 툴팁의 버튼 식별 정보도 확인한다. 전체 화면 버튼의 동작은 유지한다.

가사 시간이 맞아도 ivLyrics의 애니메이션 갱신기가 Spotify의 일시정지 상태 때문에 유휴 상태로 멈추는 문제가 있었다. 외부 재생의 시간 갱신과 탐색 때 기존 갱신기를 깨워 실제 강조 행이 이동하도록 했다. 별도 데스크톱 전송에는 현재 YouTube 곡의 시간과 재생 상태를 사용한다. 보조 앱이 상속하는 전송 함수의 수신 객체를 보존해, 보조 앱 요청이 오버레이 포트로 잘못 전송되던 문제도 수정했다.

Windows 오버레이에는 이전 곡, 재생 또는 일시정지, 다음 곡 버튼이 있다. 잠금 해제 상태에서 표시하며 커서가 창 안에 있는 동안 자동으로 다시 잠그지 않는다. 조작 중에는 일시정지 숨김 설정 때문에 버튼까지 사라지지 않으며, 창 밖으로 나가 자동 잠금되면 기존 숨김 설정을 따른다. 버튼은 창 하단 안쪽에 고정해 기본 500 곱하기 200 픽셀 창에서도 잘리지 않게 했다.

제어 연결은 기존 도우미와 데스크톱 앱 사이에서만 사용한다. Spotify 출처에서 15 분짜리 메모리 세션을 만들고 곡 식별자를 대조한 명령만 전달한다. 명령은 최대 16 개이며 10 초 뒤 만료되고 한 번만 소비한다. 5 초 동안 재생 상태가 갱신되지 않으면 버튼을 비활성화한다. 연결 토큰은 파일이나 목록 내보내기에 저장하지 않는다. 새 서비스나 자동 시작 항목은 추가하지 않았다.

실제 실행에서 기존 마이크, 재생목록과 목록 재생 버튼, 가사의 강조 행 이동, 일시정지 및 탐색을 확인했다. 도쿄 테디베어의 강조 행은 약 28 초의 5 번째 행에서 약 36 초의 7 번째 행으로 이동했고, 일시정지 상태에서 72 초로 탐색하면 14 번째 행으로 바뀌었다. 실제 데스크톱 버튼으로 YouTube를 일시정지하고 재개한 뒤 다음 Spotify 곡으로 넘어가고 이전 YouTube 곡으로 복귀하는 것도 확인했다. 원곡과 커버의 청취상 시간 일치는 별도 검수 대상이다.

PC 회귀 검사는 308 건 중 307 건이 통과했고 Windows 심볼릭 링크 권한이 필요한 1 건을 생략했다. 별도 데스크톱 앱은 화면 계층 27 건과 Rust 8 건이 통과했다. 개발 PC에는 수정한 실행 파일을 적용했으며 기존 실행 파일과 설정은 복원할 수 있게 보관했다. 진단 포트 없이 재시작한 일반 Spotify에서도 YouTube 재생과 기존 마이크의 가사 전환 및 한글 발음을 확인했다.

별도 데스크톱 원본에는 이번에 확인한 소스 범위에서 라이선스 파일이나 배포 허락을 찾지 못했다. 해당 수정 소스와 패치는 현재 개발 작업 폴더에만 보관하고 공개 배포 묶음에서는 제외한다. 원본 앱의 업데이트는 자동 확인 후 사용자가 설치를 선택하는 방식이며, 원본 업데이트를 설치하면 이 로컬 수정이 교체될 수 있다. 공개 설치 파일과 이번 개발 소스는 구분한다. 오버레이의 일부 앨범 그림과 배경색은 원본 Spotify 곡을 참조하는 기존 경로가 남아 있어 YouTube 곡과 다를 수 있다.

## 표시 정보와 오버레이 설정 후속 적용

2026년 10월 27일 후속 수정에서 검색 정보와 표시 정보를 분리했다. 가사 검색용 곡명과 원곡 가수를 바꿔도 하단 재생바, ivLyrics와 데스크톱 오버레이에는 실제 영상 제목과 업로더를 표시한다. 검색 조건은 후보 조회와 선택 및 캐시 구분에만 사용한다. 이전 전송 상태에 검색명이 남아 있어도 현재 영상 식별자가 일치하면 실제 영상 정보로 교정한다.

데스크톱 설정의 동작과 표시 조건에서 재생 버튼을 항상 표시, 마우스 오버 시 표시, 숨김 중 선택하고 크기는 24~48 px로 조절한다. 잠긴 상태에서도 표시된 버튼 영역은 클릭할 수 있게 운영체제의 클릭 통과를 해당 영역에서만 해제한다. 버튼도 기존 마우스 오버 설정의 불투명도 0, 0.2, 1과 배경 모드, 지정 색상 및 불투명도를 따른다. 완전히 투명하거나 사용자 CSS로 숨겨진 버튼의 네이티브 클릭 영역은 해제한다. 일시정지 또는 데이터 수신 시간 초과에 따른 가사 숨김은 재개 버튼까지 숨기지 않는다. 기존에 저장된 마우스 오버 시 표시와 24 px 설정을 유지했다. 사용자 CSS는 그대로 적용하지만 .overlay-container 전용 선택자를 별도 버튼 선택자로 자동 변환하지 않는다.

앞서 남긴 일부 그림과 배경이 Spotify를 참조한다는 한계 중 현재 가상 곡의 썸네일과 이미지 배경 경로를 수정했다. 실제 실행에서 도쿄 테디베어와 유령도쿄로 전환한 뒤 각 영상 그림의 디코딩 폭 480 px를 확인했다. 현재 곡의 전송만 보정하고 다른 곡 사전 조회는 원래 경로를 유지한다. 백그라운드에서 재생 상태 전송과 버튼 상태 갱신이 지연되지 않도록 각 기존 렌더러 안에 500 ms 워커를 사용한다. 워커 생성 실패 시 단일 타이머로 대체하고 종료 시 해제한다. 별도 서비스는 만들지 않았다.

유령도쿄 커버 UWa_OiXDiQA의 문제는 선택된 일본어 제목 LRCLIB 시간표가 원곡 업로더 자막보다 동일 문장 39 개 기준 중앙값 5.32 초 늦다는 것이었다. 원곡과 커버 업로더 한국어 자막의 서로 다른 문장 7 개에서는 커버가 중앙값 0.816 초 빨랐다. 전체 길이 차이만으로 시간표 적합성을 판정할 수 없었다. 해당 영상의 검색 정보만 Ghost City Tokyo와 Ayase로 지정해 원곡 자막에 더 가까운 후보를 선택했고, 실제 실행에서 48 행과 첫 행 18.24 초 및 마지막 행 198.42 초를 확인했다. 표시 제목은 실제 아오쿠모 린 커버 제목이며 한글 발음은 48 행에서 표시됐다. 이 한 곡의 비교는 모든 커버에 대한 자동 정렬을 의미하지 않으며 업로더 자막과 실제 발성 시작 시각도 구분한다.

최종 PC 회귀는 322 건 중 321 건 통과와 Windows 심볼릭 링크 권한 1 건 생략이다. 별도 앱은 화면 계층 29 건과 Rust 9 건이 통과했다. 실제 DOM의 버튼 불투명도 0.2, 투명 배경과 24 px 및 실제 영상 제목 전송을 별도로 확인했다. 운영체제 클릭 통과 플래그 전환은 진단했으나 자동화 도구의 창 활성화가 위치와 커서를 이동시키므로, 잠긴 창에서 물리적 첫 클릭 성공과 혼합 DPI 환경 전체를 검증한 것으로 간주하지 않는다. 공개 설치 파일은 이 개발판과 구분하며 외부 데스크톱 원본의 배포 허락 확인 전까지 해당 소스와 바이너리는 공개 묶음에서 제외한다.

## 문장 기준 싱크 편집기

2026년 10월 27일 후속 작업에서 기존 빠른 싱크 조절 영역에 쉽게 싱크 맞추기 창을 연결했다. 사용자는 문장을 선택하고 그 문장을 부르기 시작할 때 지금 이 문장 시작을 눌러 전체 가사를 이동한다. 시각은 클릭 처리 시작 때 읽고 비동기 저장보다 먼저 계산한다. 재생 위치나 속도는 변경하지 않는다. 반응 시간에 따른 차이는 0.1 초 버튼으로 조절할 수 있다.

입력은 0~60 초와 먼저 표시 또는 나중에 표시 방향을 따로 고르는 방식이다. 현재값도 가사를 5.3 초 먼저 표시처럼 보여준다. 0.1 초와 1 초 조절, 곡별 자동 저장, 직전 보정 취소와 원래대로를 제공한다. 전역 보정은 기존 ±10 초 범위를 유지하고 곡별 보정만 ±60 초로 확장했다. 가사 시간표가 없는 곡은 문장 맞추기를 사용할 수 없다. 가사 조회 도중 창을 열었다면 문장 목록 새로 불러오기로 현재 자료를 읽는다.

보정은 기존 ivLyrics IndexedDB에 저장한다. YouTube 영상과 Spotify 곡의 식별자를 구분하고, 가사 화면이 마지막 Spotify 곡 대신 현재 가상 곡의 보정값을 읽도록 수정했다. 백업 정규화도 올바른 YouTube 식별자와 ±60 초 값을 보존한다. 곡이 바뀐 편집기의 저장은 거절하며 저장 실패를 성공으로 표시하지 않는다. 검색명과 표시명은 바꾸지 않는다.

원본 ZIP은 그대로 유지하고 scripts/patch_ivlyrics_sync.py가 빌드 단계에서 지정된 소스 세 파일을 수정한다. 원본 구조의 필수 지점이 달라지면 적용을 중단한다. 관리 파일의 무결성 목록은 수정 후 코드로 만든다. 원본을 갱신할 때도 같은 변환과 계약 검사를 통과해야 한다. ivlyrics-sync.js와 ivlyrics-sync-ui.js가 자체 구현이며 외부 데스크톱 EXE 변경은 이번 기능에 필요하지 않다.

자동 검사는 348 건 중 347 통과와 Windows 심볼릭 링크 권한 1 건 생략이다. 개발 PC의 실제 UI에서 5.3 초 입력과 DB의 5300 값, 데스크톱 전송기의 -5300 값, 취소 및 초기화 후 0 복원을 확인했다. 문장 선택과 클릭 순간 시각에 따른 보정 계산도 확인했다. 시간표를 음성과 자동 비교하는 기능은 아니며 전체 음성의 발성 시작을 검수한 결과로 간주하지 않는다. 실행 기록과 보존한 원본은 work/runtime/RUNNING.md를 참조한다.

## 현재 재생 중 패널 디자인

2026년 10월 27일에 YouTube 현재 재생 중 패널의 표시 계층을 별도 컴포넌트로 정리했다. Spotify의 색상과 글꼴 변수를 사용하고 제목과 가수, 실제 재생 방식, 음원과 영상 선택, 가사 및 검색 정보 조작을 구분한다. 긴 제목은 줄바꿈하며 반복 상태 갱신에서 텍스트 노드를 교체하지 않는다. 검색용 별칭은 표시 제목에 쓰지 않는다.

곡 또는 실제 재생 방식이 바뀔 때만 180 ms 전환을 사용하고 동작 줄이기 설정을 따른다. 영상 영역은 최소 높이 200 px를 유지하고 버튼과 로딩 및 오류 안내는 영상 밖에 둔다. iframe은 최초 구성 때 한 번 넣고 이후 위치 변경과 상태 갱신에서 다시 만들거나 옮기지 않는다. 음원 표지는 별도의 형제 요소로 표시한다. 영상 오류의 재시도는 같은 곡과 시간 및 재생 의도를 유지한다. 기존 링크 재생 종료 동작은 Spotify의 이전 재생을 복원하므로 버튼 설명에도 이를 표시한다.

실제 제품 파일로 만든 로컬 미리보기의 영상, 음원, 로딩 및 오류 네 상태를 320 px와 420 px 패널에서 검사했다. 내부 16 px 여백을 포함한 영상 영역은 각각 288×200 px와 388×218.25 px였으며 가로 넘침과 JavaScript 오류는 없었다. 표지와 영상은 로컬 대체 자료이므로 실제 YouTube 재생이나 광고 검증을 의미하지 않는다. DOM 회귀 11 건과 탐색 및 재시도 27 건을 포함한 전체 검사는 406 건 중 405 통과와 Windows 심볼릭 링크 권한 1 건 생략이다.

개발 PC에는 일반 실행 경로로 수정본을 적용했다. 파일 제공 경로의 JavaScript와 CSS가 모두 올바른 형식으로 응답하는 것을 확인했다. 실제 Spotify 패널의 추가 재생 확인은 별도 실행 증거와 구분한다. 관련 증거는 work/now-playing-preview-proof.json과 work/now-playing-compatibility.json 및 .log다. 공개 설치 파일의 배포와 이 개발판 적용은 구분한다.

후속 실제 화면 검증에서는 정상 실행한 Spotify의 로컬 혼합 목록에서 유령도쿄 커버를 선택했다. 새 현재 재생 중 패널의 제목과 가수, 영상 영역과 재생 방식 선택 및 가사 버튼이 표시됐고 영상과 하단 재생 시간이 진행되는 것을 확인했다. 마지막에는 기존 재생바의 버튼으로 약 1분 35초에서 일시정지했다. 새 패널과 YouTube 재생 버튼 및 일시정지 상태를 접근성 트리에서도 확인했으며 증거는 work/now-playing-live-ui-proof.json에 남겼다. 이 확인은 영상 재생과 표시 연결에 해당하며 광고 실제 노출과 음원 방식 전환을 추가 실측한 결과는 아니다.
